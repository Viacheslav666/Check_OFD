Агент ОФД для RDP клиента (Windows Server 2019/2016/2022 x64, без Docker)
========================================================================

В архиве уже есть Java 21 (папка jre) и WinSW — ставить ничего не нужно.

УСТАНОВКА (PowerShell от имени администратора, в папке распакованного архива):

  Set-ExecutionPolicy -Scope Process Bypass -Force
  .\Install-Agent.ps1 -Inn 635001808204 -Name "РДП Самара"

  - ключ API ОФД скрипт спросит скрытым вводом (или параметр -ApiKey "...");
  - белый список IP по умолчанию: 192.168.31.196 (IP центрального приложения),
    другой адрес: -AllowedIps 192.168.31.196,10.10.50.2;
  - порт по умолчанию 18500 (-Port).

  Скрипт установит агента в C:\OFD-Agent, создаст agent.yml, службу Windows «ofd-agent»
  (автозапуск) и правило брандмауэра «OFD Agent 18500» только для IP из белого списка.
  В конце выведет имя, IP, порт и ТОКЕН — внесите их в ЛК центрального приложения
  (вкладка «Агенты» → «Новый» → «Сохранить» → «Проверить связь»).

СМЕНА IP ЦЕНТРАЛЬНОГО ПРИЛОЖЕНИЯ (без переустановки и перезапуска):

  C:\OFD-Agent\Set-AgentAllowedIps.ps1 -AllowedIps 192.168.31.200
  C:\OFD-Agent\Set-AgentAllowedIps.ps1 -Show

  Скрипт меняет allowed-ips в agent.yml и правило брандмауэра; агент применяет новый список
  в течение ~10 секунд. Можно и вручную отредактировать allowed-ips в C:\OFD-Agent\agent.yml —
  агент подхватит его сам, но тогда правило брандмауэра нужно поменять тоже вручную.

ОБНОВЛЕНИЕ: распакуйте новый архив и запустите из него .\Update-Agent.ps1
  (agent.yml, ключ, токен и локальная база сохраняются; при неудаче — откат).

УДАЛЕНИЕ:   C:\OFD-Agent\Uninstall-Agent.ps1            (папка с agent.yml и данными остаётся)
            C:\OFD-Agent\Uninstall-Agent.ps1 -RemoveData (удалить всё, включая ключ ОФД)

ЛОГИ: C:\OFD-Agent\data\ofd-agent.log, C:\OFD-Agent\ofd-agent.out.log / .err.log
СЛУЖБА: Get-Service ofd-agent; Restart-Service ofd-agent
